## 二、本项目明确不做

- 不用 `pywinauto` / OCR / 外挂驱动同花顺 `xiadan.exe` 自动下单
- 不用 miniQMT / xtquant 独立进程、文件单、HTTP / socket 桥接、外部 IDE 跑实盘策略
- 不在公有云、公有云桌面、虚拟机、券商机房部署交易终端或指令生成系统
- 不破解客户端接口、不 Hook / 内存注入、不反采行情
- 不代他人操作、不设子账户/分仓、不对外售卖工具或提供含投资判断的软件
- 不在未取得券商确认反馈前开始程序化交易

## 三、本项目必须做

1. 只用本人实名账户、本人资金、本人实体机。
2. 使用券商官方渠道提供的标准版 QMT 安装包，不用第三方安装包。
3. 签署《程序化交易委托协议》《程序化交易风险揭示书 / 承诺书》。
4. 首次交易前向券商如实报告：账户基本信息、资金规模及来源/杠杆、策略类型及主要内容、指令执行方式、**最高申报速率、单日最高申报笔数**、交易软件名称与版本及开发主体、联络信息。**收到券商确认反馈后方可交易。**
5. 重大变更（策略、软件、报单速率、资金规模、杠杆来源、停止程序化交易）在变更发生后次月第 5 个交易日前做变更报告。
6. 控制报撤频率远低于高频标准；避开四类异常交易监控：瞬时申报速率异常、频繁瞬时撤单、频繁拉抬打压、短时间大额成交。
7. 保留 append-only 审计日志与每日对账记录，随时可一键停用。

## 四、报告义务触发情形（《关于股票程序化交易报告工作有关事项的通知》）

以下任一即触发，**注意第 4 条：自建策略 + 自建下单程序本身就在报告范围内**：

1. 证券代码、买卖方向、委托数量、委托价格及下达时间均由计算机自动决定
2. 1 天内出现 10 次以上「1 秒内 10 笔以上申报（含撤单）」
3. 最近 30 个交易日日均交易单市场股票 ≥50 只且年化换手率 >30 倍
4. 使用自主研发或其他定制软件
5. 交易所认定的其他情形

仅使用券商自带条件单/网格且不触发上述条件的，无需报告 —— 这也是「本地信号 + 人工逐笔确认」被推荐为起步模式的原因。

## 五、合规边界一句话

> 监管禁止的是「绕过券商可管可控可穿透体系」，不是程序化交易本身。本项目的实时指令生成与执行全部留在券商沙箱内；本地自建平台只做盘前备料与盘后复盘。

## 六、本轮已确认事项（2026-11-07）

| 项目 | 结论 |
|---|---|
| 开户券商 | 浙商证券；已开通 QMT（仍需确认是标准版内置 Python 沙箱） |
| 架构 | **接受**实时决策与下单闭环在券商沙箱内、自建平台只做盘前盘后 |
| 交易前端 | **同花顺看盘 + 券商 QMT 执行**，同花顺不再承担下单 |
| 用户目标 | 账户 → 盘中实时选股 → 指标达标 → 自动买卖。已在 `execution/qmt/` 完整实现（定时器全推行情、两级筛选、风控、幂等下单、回报轮询、对账熔断） |
| 唯一剩余硬阻塞 | **尚未收到券商对程序化交易报告的确认反馈**；在此之前 `live_config.py` 保持 `REPORT_CONFIRMED=False`，`effective_dry_run()` 强制不调用 `passorder` |

**注意「使用我提供的账户」的正确理解**：账户由本人在浙商证券 QMT 客户端本机登录，凭据由券商终端加密保管。策略代码只需资金账号（`ACCOUNT_ID`，非密码）来查询与下单，日志中账号脱敏。**不要向任何第三方、包括本项目或对话助手提供交易密码 / 资金密码**。

另外，QMT 内置 Python 策略的文件读写与外部网络受限，本项目执行层完全不依赖它们；本地 Web 配置台保存的只是规则 JSON，两者之间不存在、也不允许存在实时文件/HTTP/socket 桥接。
